# meta-arty-z7

Yocto BSP layer for the Digilent Arty Z7-20 (Zynq-7000 xc7z020, 512 MB DDR3,
console UART0). Adds machine `arty-z7-20` on top of meta-xilinx-core's
`zynq-generic`, with U-Boot SPL replacing the Xilinx FSBL — no Vivado input
anywhere in the build.

The board has no current support anywhere upstream (no devicetree in mainline
Linux or U-Boot, no machine in meta-xilinx), so this layer carries:

- `conf/machine/arty-z7-20.conf` — machine on top of zynq-generic; SPL boot
  flow, out-of-tree runtime devicetree via meta-xilinx's `device-tree` recipe.
- `recipes-bsp/platform-init/` — Digilent's generated `ps7_init_gpl.c/.h`
  (PLL/DDR/MIO setup, linked into SPL). Taken verbatim from
  github.com/Digilent/Petalinux-Arty-Z7-20 @ 43dca7d (HSI 2017.4).
- `recipes-bsp/device-tree/` — Linux devicetree, derived from Digilent's
  zynq-artyz7.dts (u-boot-digilent @ 3b9fb209) and the BSP system-user.dtsi,
  restructured after mainline zynq-zybo-z7.dts.
- `recipes-bsp/u-boot/` — one patch adding the U-Boot control devicetree
  (kept in sync with the Linux one by hand — fixed MAC and PHY address exist
  in both) plus a config fragment selecting it.

The board has no factory MAC; both devicetrees set the fixed locally
administered address `02:44:5a:37:32:30` on gem0.

## Provenance of board-specific inputs

### `ps7_init_gpl.c/.h`

The Zynq-7000 Processing System (PS) needs its PLLs/clocks, DDR memory
controller and MIO pin-muxing configured through the System Level Control
Registers (SLCR, based at `0xF8000000`) before there is usable DRAM or a
console. That low-level init is board-specific — it depends on the exact DDR3
part, the PS clock, and the MIO pin assignments — so the Xilinx tools generate
it as a table of register writes (`EMIT_WRITE`/`EMIT_MASKWRITE`/`EMIT_MASKPOLL`;
the header states "This file is automatically generated"). It is normally run
by the Xilinx FSBL. Here U-Boot SPL replaces the FSBL, so the same init is
compiled into SPL through meta-xilinx's `platform-init` recipe (enabled via
`FORCE_PLATFORM_INIT` in the machine conf).

Because the board has no upstream hardware description, this init cannot be
regenerated without Vivado. It is therefore taken **verbatim** from Digilent's
own Petalinux BSP:

- `github.com/Digilent/Petalinux-Arty-Z7-20` @ `43dca7d` (master), file
  `Arty-Z7-20/project-spec/hw-description/ps7_init_gpl.{c,h}`, generated by
  Xilinx HSI 2017.4.

To confirm it is correct for this board, it was cross-verified as functionally
identical (same PLL/DDR/MIO register writes) to Digilent's U-Boot port
`u-boot-digilent@3b9fb209`, `board/xilinx/zynq/zynq-artyz7/`. The header is
`(c) Copyright 2010-2014 Xilinx, Inc.` under GPL-2.0-or-later — hence the file
stays GPL (see Licenses below).

### Device trees

The Linux runtime devicetree is derived from Digilent's `zynq-artyz7.dts`
(`u-boot-digilent@3b9fb209`, GPL-2.0+) and the BSP `system-user.dtsi`,
restructured after mainline `zynq-zybo-z7.dts`. The U-Boot control devicetree
is a hand-maintained counterpart kept in sync by hand (the fixed MAC and PHY
address appear in both).

## Dependencies

- openembedded-core / poky (scarthgap)
- meta-xilinx (meta-xilinx-core, scarthgap) and its dependency meta-arm

Mender integration lives in the parent layer meta-mender-xilinx (this BSP is
nested inside it); the `:mender-*`-gated lines in the machine conf are inert
without it.
